# CI/CD Final Project — Flask Service

This repository contains a small Flask HTTP service and CI/CD configuration for the IBM Skills Network / Coursera Continuous Integration and Continuous Delivery final project.

## Project details

- **Project name:** CI/CD Final Project
- **Application:** Flask service
- **Runtime:** Python 3.9
- **Application port:** 8000
- **Health endpoint:** `/health`
- **Run marker:** `SERVICERUNNING on port 8000`
- **CI:** GitHub Actions, flake8, and nose unit tests
- **CD:** Tekton / OpenShift Pipelines (cleanup, git-clone, flake8, nose, buildah, deploy)

## Run locally

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
flake8 service tests
nosetests -v
PORT=8000 gunicorn --bind 0.0.0.0:8000 service:app
```

Open `http://localhost:8000/` or `http://localhost:8000/health`.

## GitHub Actions

The workflow is in [`.github/workflows/workflow.yml`](.github/workflows/workflow.yml). It installs Python dependencies, runs flake8, then runs nose tests for pushes and pull requests.

## OpenShift / Tekton

- Task definitions: [`.tekton/tasks.yml`](.tekton/tasks.yml)
- Pipeline definition: [`.tekton/pipeline.yml`](.tekton/pipeline.yml)
- PVC manifest: [`openshift/pvc.yml`](openshift/pvc.yml)

The PVC manifest requests 1Gi and uses the lab storage class `skills-network-learner`. Apply it only in the provided course cluster. The Tekton Pipeline expects the catalog Tasks `git-clone`, `buildah`, and `openshift-client` to be installed in the target namespace.

Before running the pipeline, set the `image` pipeline parameter to an image repository writable by your OpenShift project and ensure the service account has permission to push and deploy. The cluster-specific application screenshots and logs must be captured from an actual PipelineRun; they are not generated by this repository.
